# Accuracy pass, 2026-10-07 (branch `accuracy`)

*Owner: "now work on the accuracy". Three changes, each measured against a run of the same code with only that change undone. Nothing here was tuned on a held-out set.*

## 1. Completed IPC text (80 sections)

**Defect.** civictech's `ipc.json` carries only the operative paragraph of each section, and for 55 sections not even that: s300 ends at "culpable homicide is murder" (no clauses, no Exceptions), s506 at "or with both;" (no threat-to-kill limb, 7 years), s307 without the life-convict clause. This text feeds retrieval, the Node 2b judge, Node 4 and the section drawer.

**Fix.** `scripts/ipc_official_text.py` parses the official text (Goa Police copy of the Legislative Department consolidation, sha256 `576a485b...`, the file s304B was already patched from) and writes `"mode": "complete"` patches to `data/mappings/statute_patches.json`; `parse_ipc` applies them only while civictech's text is still a prefix of the patch, and fails the build otherwise.

| | sections |
|---|---|
| same as the official text | 361 |
| completed | **80** |
| held back: amended after 1997 in the part civictech dropped (`POST_1997`) | 6 (4, 40, 100, 118, 119, 120) |
| rejected: the source's block holds another section's text | 4 (171H, 214, 221, 405) |
| differ mid-text or civictech longer (civictech is the newer law: 2000-2018 amendments) | 54, untouched |

The source is a **1997** consolidation (no current official text is reachable from this network), which is why only prefix-continuations are applied. Gaps in the source (s214 running into s216, s221 ending with s222's last limb) were caught by a gap rule and a 45-word shared-run rule; 6 gap cases were read and allowed. Rules pinned in `tests/ingest/test_ipc_official_text.py`.

**Neutral.** Every difference is one or two sections, within the run-to-run variation recorded on 2026-10-06; the threat-set difference is mostly one case (#6: 2 extras vs 5). The change is kept because it is the correct law - Node 2b and Node 4 now read 300's Exceptions and 506's 7-year limb - not because it scores better.

**Hypothesis refuted.** CLAUDE.md suspected the cut-short 506 caused "threat to kill charged as attempt to murder". It did not: 506 ranked 1st-4th in all four IPC threat cases before the fix (2nd-7th after), and the mango-tree axe threat is charged 307 with either text. That error is in Node 1 and the judge, not the data.

## 2. Court orders that state no allegation are declined (`nofacts`)

**Defect.** 4 of the 20 fresh external orders (ext0040-0059) were pure procedure ("Heard... permission to withdraw... disposed of"). Intake said so, then the pipeline ran on the procedure anyway and charged IPC 173, 174, 204, 224 (a withdrawn bail plea) and 173 (a 498A quashing order): real sections, verified, wrong. One of the four "hit" only by luck (341).

**Fix.** When intake's flag AND its empty extraction agree, `graph.run` returns `insufficient_data` with reason `no_facts_stated` and no LLM call, and the report asks for the FIR or the allegations. No nearest sections are listed: for procedural text they are the summons/custody offences. Never reached by a plain fact statement (intake only runs on text that reads as a court order). Switch: `PRAMANA_ABLATE=nofacts`.
