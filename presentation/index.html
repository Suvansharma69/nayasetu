The name is Sanskrit for proof, and that is the design goal: nothing reaches the lawyer unless it can be proved from data the system actually holds. A lawyer gives it the facts of a case and the date of the offence. It works out which criminal code applies, finds the sections the facts disclose, checks every one against the statutes, finds precedents, drafts counter-arguments and shows how appeals on those sections were decided. All of it runs offline on a laptop, at zero cost.

01 · The problem · renumbering

On 1 July 2024 India renumbered its criminal law.

No such section. The BNS ends at 358.

A section number means nothing without its code, and the offence date decides the code.

The Bharatiya Nyaya Sanhita replaced the Indian Penal Code on 1 July 2024, and almost every offence got a new number. Offences committed before that date are still tried under the IPC, so for years every lawyer works with both codes. [click] 302 is murder in the IPC; in the BNS it is hurting religious feelings. [click] 303 was murder by a life-convict; in the BNS it is theft. [click] And 420, the best-known cheating section, does not exist in the BNS at all. [click] So a citation that is right in one code is a different crime, or nothing, in the other. The offence date decides which code applies.

And the facts are confidential

A lawyer types a client’s real facts. They should never be sent to a cloud AI service, so the whole system has to run on the lawyer’s own machine.

The second problem: language models invent citations. Published studies found this even in commercial legal research tools. This is the very model inside Pramana. Asked what BNS 303 covers, it confidently described a bomb-threat offence. [click] BNS 303 is theft. [click] When we let it answer from memory, 20 of its 68 citations named sections that do not exist in the BNS, mostly old IPC numbers. [click] And a lawyer will type real client facts into this tool, so sending them to a cloud AI service is not acceptable. Whatever we build has to be accurate about citations and has to run locally. That is exactly what Pramana does.

03 · How it works · the pipeline

The model proposes. The graph decides.

Deterministic code
Language model
Graph lookup
Built offline ChromaDB · 4 collections Citation graph · NetworkX Outcomes · SQLite
This is the whole pipeline, and the key idea is in the title: the model proposes, the graph decides. Solid boxes are ordinary code; dashed boxes are the language model, which is used in only three places. The router picks the code from the date with a plain rule, no AI. Retrieval finds candidate sections two ways: by similarity to the statute text, and by votes from similar past judgments, fused by rank fusion. A guardrail stops early if the facts are nowhere near our data. Node 1 proposes sections; Node 2 checks each one against the citation graph and sends rejections back with the reason. Node 2b asks whether a real section actually fits the facts, backed by legal rules such as headcounts for unlawful assembly. Precedents and outcome statistics run in parallel, Node 4 drafts counter-arguments, and a final check re-verifies anything new. [click] Three stores are built once, offline: a vector database, the citation graph, and an outcomes table.

Then a second check: does each real section fit the facts? Doubts are shown to the lawyer, never hidden.

This is the heart of the system. We built a graph from the data we actually ingested: every section of both codes, every judgment, an edge whenever a judgment cites a section, and a reviewed bridge from each IPC section to its BNS counterpart. On the left is a real piece of it, around theft. The rule is simple: a section is real only if it is a node of the code the router chose. When the model proposes something that fails, it goes back with the reason. This is a real stress-test run with retrieval withheld. [click] Round 0: the model says 421. Rejected: the BNS stops at 358. [click] Round 1: it says 378, the old IPC theft section. Rejected, but the graph supplies a hint: its BNS counterpart is 303. [click] Round 2: 303, verified. [click] The graph passed its gate 20 out of 20, telling real section numbers from invented ones, including traps like BNS 420. And existing is not the same as applying, so a second check tests each real section against the facts and shows any doubt to the lawyer.

Precedents come only from graph edges, so every precedent really did apply the charged section. That creates a problem for new cases. [click] In our corpus not one judgment applies BNS 303 yet; BNS theft cases have not reached the higher courts in bulk. [click] So Pramana crosses the reviewed mapping to the old IPC sections: 378 with 11 judgments and 379 with 158. The law of theft did not change, so that precedent still counts. All 575 rows of the mapping were reviewed against the official gazette text. [click] The judgments are ranked by similarity to the facts, and near-identical companion appeals are removed so you don’t see one judgment three times.

The technology, layer by layer from the bottom. Data: the full IPC, the BNS parsed from the official gazette because no trustworthy digital copy existed, and about 2,700 Supreme Court and High Court judgments. Knowledge: a ChromaDB vector store, the NetworkX citation graph, and SQLite for outcomes. Intelligence: BGE-M3 for embeddings, which we chose by measurement, and a 4-billion-parameter Qwen model served locally by Ollama. Orchestration: LangGraph, which gives us the retry loop and parallel steps. And a FastAPI backend with a web interface. Everything is open-source and runs on one laptop with a 4 GB graphics card. The next gain: wider retrieval

Minor companion offences such as simple hurt (323) or insult (504) rarely reach the candidate list: 37% of the right sections did. Widening retrieval is the clearest next step.

We also tested Pramana on IL-TUR, the published Indian legal benchmark from ACL 2024. The best systems on it are trained on 42 thousand labelled documents and score 28.1. Pramana has no training on this task at all: it is a 4-billion-parameter model on a laptop, and it scores 11.8 on the test split, which we ran once at the very end. So the trained systems lead on this task, and we say so plainly. They are classifiers built for this one benchmark; Pramana also routes the code, finds precedents, drafts arguments and explains its doubts. [click] Pramana is strong on serious offences: murder at 0.78. [click] The gap is mostly minor companion offences, such as simple hurt or insult, which rarely reach the candidate list. That tells us exactly where to improve next: retrieval coverage, not a bigger model.
